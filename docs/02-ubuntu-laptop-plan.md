## 1. 目标

把 02 页变成一台正在运行 macOS Mojave 的拟真 2015 Retina MacBook Pro。五个思想主题以 Finder 桌面文件夹出现，用户可按真实 macOS 桌面习惯选择、双击、打开、移动、聚焦与关闭。01↔02、02↔03 通过 MacBook 开合完成视觉衔接，任意时刻都可反向，当前角度、位置与速度连续保留。

成功后的 02 应同时成立：

- 第一眼像在暖色摄影棚里拍摄的真实旧 MacBook，铝制机身、黑色玻璃边框、屏幕、转轴、键盘和接触阴影具有可信体积。
- macOS Finder 桌面承担“思考索引”的信息结构，五个主题仍能快速扫描。
- 文件夹和窗口遵循桌面系统的行为预期，所有可见核心控件都有真实反馈。
- 页面切换保留项目现有的三页 PPT 式节奏，笔记本开合成为 02 专属的物理转场。
- 动画支持中断、反向、连续滚轮输入与减少动态效果偏好。
- 01 的 World Compiler 和 03 的文章版式保持当前视觉基线。

本分支仅记录方案与持久化设计决策。组件、样式、素材、依赖和运行逻辑留到审核后的实现 session。

## 3. 推荐视觉方向

### 3.1 主方向：2015 Retina MacBook Pro 私人工作站

采用 2015 Retina MacBook Pro 与 macOS Mojave 的视觉语言，呈现一台长期使用、保存着个人思考资料的私人工作电脑：

- 机身：暖银色一体成型铝合金，边缘倒角、细密拉丝、轻微氧化与小范围使用擦痕保持真实克制。
- 结构：2015 款 Retina 比例、黑色玻璃屏幕边框、中央隐藏式转轴、黑色巧克力键盘和玻璃触控板；C 面完整建模，最终构图只露出转轴和一小段被强烈压缩的键盘线索。
- 项目呼应：暖银铝材承接 01 的金属质感，暗部保持棕黑石墨色，高光保持暖奶油色；桌面外继续使用现有纸张背景。
- 摄影语言：约 55mm 镜头感，相机位于真实使用者坐姿的眼睛方位，光轴朝向屏幕中心；屏幕接近正视，只保留极小俯角；搭配柔和暖主光、右后方轮廓光、桌面接触阴影和克制胶片颗粒。
- 最终姿态：屏幕约 104°–108° 打开，横向偏航控制在 2° 内，垂直俯角控制在 3° 内；透视接近人眼正面使用电脑时的观感，屏幕文字与窗口保持端正清晰。
- 使用痕迹：细微灰尘、键帽油光、铝壳轻擦痕与转轴暗部；外壳标志保持低对比，痕迹密度干净、克制。

这一路线与 01 的机械物件、金属质感和暖色照明连接最自然，也能让 03 的纸面编辑风格在笔记本合拢后顺畅出现。

### 3.2 屏幕桌面

- 壁纸采用原创或生成的低饱和暖沙色到炭黑渐变，加入非常浅的因果网格或系统拓扑纹理，呼应“万物皆为代码”，避开 macOS 默认风景壁纸的广告感。
- Mojave 蓝只用于文件夹选中态、窗口焦点和极小系统标记，面积受控。
- 五个文件夹以 3+2 的松散网格放在桌面左上区域，保留真实桌面的自然空白。
- 顶部保留 Mojave 风格菜单栏：系统菜单、Finder、文件、编辑、显示、前往、窗口、帮助、状态图标和真实时间。
- 底部保留克制 Dock：Finder、文稿阅读工具、已打开窗口与废纸篓。出现的应用与状态指示全部可响应。
- 文件夹、工具栏和 Dock 图标采用经许可核对的高质量资源；字体使用系统 `-apple-system` 栈并准备视觉相近的网页回退字体，避免再分发系统字体文件。
- 屏幕加入极轻的雾面反射、像素纹理和边缘亮度衰减，文字对比度始终达到可读标准。

### 3.3 构图

桌面端让笔记本占据页内约 72%–82% 宽度。屏幕是绝对主体，C 面可见高度控制在整机画面的 18% 内，只保留转轴、后侧键盘和极窄机身边缘；完整触控板与大面积掌托位于画面裁切之外。1280×720 下完整看到屏幕与转轴，并保留一条可信接触阴影；页码导航与固定页头保持无遮挡。

移动端继续使用正视屏幕的构图，C 面进一步收窄，完整保留屏幕和转轴。窗口自动占满屏幕工作区，文件夹排列为两列。

## 4. 桌面交互规格

### 4.1 文件夹

| 操作 | 反馈与状态 |
| --- | --- |
| 单击 | 选中文件夹，出现 macOS 蓝色名称底色；其他文件夹取消选中。 |
| 双击 | 打开对应文件窗口；已打开时聚焦现有窗口并提升层级。 |
| 点击空白桌面 | 清除选择。 |
| 拖动 | 文件夹跟随指针并吸附到隐形网格；位置限制在屏幕安全区。 |
| 右键 | 打开 Finder 风格上下文菜单；“打开”“显示简介”“整理”均可执行。 |
| `Command+O` | 打开当前键盘选中的文件夹。 |
| `Return` | 进入所选文件夹的重命名状态；`Escape` 取消，确认后只更新本地显示名。 |
| 方向键 | 在文件夹网格中移动键盘选择。 |

桌面图标位置建议写入版本化 `localStorage`，刷新后保持；语言切换和响应式断点变化只重新约束坐标。提供“恢复默认位置”清除该键。

### 4.2 文件窗口

- 同一文件夹最多存在一个窗口实例。
- 标题栏支持拖动；窗口始终限制在屏幕范围内。
- 红色关闭、黄色最小化和绿色全屏三个可见控件均有完整行为。
- 全屏在 MacBook 屏幕内部进入独立桌面空间，菜单栏与 Dock 自动退场；`Escape` 或绿色控件返回原窗口状态。
- 最小化窗口缩入 Dock；点击对应 Dock 项恢复并聚焦。
- 窗口焦点决定层级、标题栏色彩、控件饱和度和 Dock 运行状态。
- `Command+W` 关闭当前窗口，`Command+M` 最小化，`Escape` 关闭最上层上下文菜单、简介面板或全屏状态。
- 页面离开 02 时保留窗口、选择和图标位置。笔记本合盖表现为系统休眠，返回 02 后恢复原桌面状态。

文件夹窗口使用简化 Finder 结构：交通灯控件、工具栏、侧边栏、路径栏和内容区。内容区只呈现一个 `README.md`；双击后通过 Quick Look 风格阅读面板打开，关闭面板返回文件夹。所有可见导航控件保持可用。

### 4.3 触控

- 第一次点击选择，450ms 内第二次点击同一文件夹打开。
- 文件夹和窗口拖动使用指针捕获，拖动期间屏蔽页面纵向手势。
- 小屏窗口自动占满屏幕工作区，省去难以操作的自由窗口布局。
- 核心触控目标至少 44×44 CSS px。

### 4.4 页面导航与桌面输入仲裁

02 同时包含“网页换页”和“桌面操作”，输入所有权需要明确：

- 手势从可滚动窗口内容开始时，窗口优先滚动。
- 窗口到达边界后，当前滚轮事务结束；下一次独立滚轮事务才可切页，防止误离开。
- 手势从屏幕空白、机身或页面背景开始时，沿用全站页面切换。
- 文件夹拖动、窗口拖动、双击和上下文菜单期间，页面导航暂停。
- 键盘焦点位于桌面时，方向键属于文件夹网格；`PageUp` / `PageDown` 仍切换页面。
- 页面右侧 01/02/03 进度按钮始终可用，作为稳定的退出路径。
- Mac 触控板事务继续锁定最初的事件目标，直到手势空闲。

## 5. 可中断、可逆的开合转场

### 5.1 单一连续状态

页面控制器从“固定 760ms 锁”升级为一个连续标量：

```text
pagePosition: 0.0 = 01 settled
pagePosition: 1.0 = 02 settled
pagePosition: 2.0 = 03 settled
```

控制器同时保存 `targetPage`、当前位置、速度、排队方向和当前滚轮事务。所有页面位移、透明度、相机、笔记本位置、转轴角度、屏幕亮度和交互启用状态都由 `pagePosition` 派生。

反向输入只改变目标，弹簧从当前数值与速度继续计算。视觉部件使用同一进度函数，任何中间点都不存在跳帧、重置或端点替换。

### 5.2 01 → 02：开盖进入

`entry = clamp(pagePosition, 0, 1)`：

| 区间 | 视觉行为 |
| --- | --- |
| 0.00–0.16 | 合拢笔记本从画面下缘进入，接触阴影先出现；01 轻微后退和降对比。 |
| 0.10–0.78 | 屏幕从约 6° 连续打开到 106°；基座有极小反作用位移，转轴保持机械支点。 |
| 0.38–0.68 | 屏幕背光从黑场升起，先出现壁纸，再出现面板与文件夹。 |
| 0.68–1.00 | 相机缓慢靠近并校正到易读角度；机身完成 1%–2% 的阻尼沉降。 |

从 02 返回 01 时沿同一路径反向：桌面渐暗、盖板连续合拢、合拢设备离开，01 恢复完整清晰度。

### 5.3 02 → 03：合盖切出

`exit = clamp(pagePosition - 1, 0, 1)`：

| 区间 | 视觉行为 |
| --- | --- |
| 0.00–0.18 | 桌面交互冻结，背光和屏幕反射平滑降低；窗口状态仍保存在内存。 |
| 0.08–0.72 | 屏幕围绕同一转轴合拢；基座保持接触面，镜头轻微拉远。 |
| 0.48–0.90 | 03 的纸面内容从后方上移并获得清晰度，合拢设备向下方退场。 |
| 0.82–1.00 | 接触阴影收束，03 完全接管输入与无障碍语义。 |

从 03 返回 02 时，这段路径精确反向：合拢设备先回到桌面，再开盖恢复原桌面会话。

### 5.4 导航策略

- 反方向输入立即清空队列并重定向，保留当前速度。
- 同方向连续输入最多排队一个相邻页面，当前段稳定后顺序进入下一段。
- 页头链接、页码和 URL hash 可直接设置目标页；跨两页导航依次经过 02 的两段物理动画。
- 语义上的当前页在转场稳定后更新，转场中的目标页先保持 `inert`；02 只在屏幕接近完全打开且速度稳定时接受桌面输入。
- 名义稳定时间目标为 850–1050ms，具体体感通过视觉原型调参。每帧按真实 elapsed time 积分，并限制异常大时间步。

### 5.5 减少动态效果

`prefers-reduced-motion: reduce` 下采用短交叉淡化：02 直接显示稳定打开、接近正视的笔记本；页面输入立即结算；视差、沉降、镜头移动与转轴过程停用。桌面交互完整保留。

## 6. 技术方案

### 6.1 推荐结构：Three.js 实体设备 + DOM 桌面

实体机身使用 Three.js 参数化几何和 PBR 材质，桌面与窗口使用真实 HTML。这个组合同时满足摄影级体积、可逆转轴动画、清晰文字、原生点击/双击、键盘焦点和无障碍语义。

实现要点：

- 屏幕盖板是以真实转轴为 pivot 的 Three.js group；基座、转轴、键盘、触控板和盖板共享场景。
- 键帽、通风孔和重复紧固件使用 `InstancedMesh`。
- DOM 桌面按 Three.js 屏幕平面的四个投影角点计算 CSS `matrix3d`，始终贴合屏幕内框。
- WebGL 层负责机身、边框、反射、阴影和景深感；DOM 层负责桌面、文件夹、窗口、焦点与输入。
- 屏幕内框提供严格裁切；盖板角度接近闭合时桌面层同步降亮度并停用指针。
- Three.js、几何辅助和纹理继续动态导入，首屏 React 包保持轻量。
- WebGL 初始化失败时显示静态打开设备框架与完整 DOM 桌面，核心内容仍可访问。

纯图片帧序列在固定角度下具有高真实度，同时带来屏幕透视同步、可逆中断、文件体积与响应式裁切成本。全 CSS 设备实现速度较快，摄影级金属、转轴和自遮挡质量较弱。混合 Three.js/DOM 路线更符合当前 World Compiler 的材质基线与项目能力。

### 6.2 React 结构建议

```text
App
├── Header
├── PageViewport
│   ├── PageSlide 01 / Hero
│   ├── LaptopTransitionLayer
│   │   ├── LaptopStage        (lazy, Three.js)
│   │   └── MacDesktop         (DOM)
│   │       ├── DesktopFolder × 5
│   │       ├── FolderWindow × n
│   │       ├── ContextMenu
│   │       └── DesktopPanels
│   ├── PageSlide 03 / EssayQueue
│   └── PageProgress
└── live region
```

`LaptopTransitionLayer` 作为三个 slide 的兄弟层，才能在 01↔02 和 02↔03 期间保持设备连续存在。02 的可访问标题与桌面内容留在该层中，稳定态对应 `#index`。

组件保持按职责拆分；动画数值集中在页面控制器和 LaptopStage 的 pose API。桌面窗口状态使用一个小型 reducer，避免为单页引入通用窗口管理框架。

## 7. 性能与渲染约束

- 02 接近视口时才预加载 Three.js 舞台和视觉资产。
- 桌面 DPR 上限 2，移动端上限 1.5。
- 笔记本场景目标不超过 35 个 draw calls；键帽和重复件实例化。
- 只有页面弹簧、转轴、相机或指针反馈处于活动状态时持续渲染；静止后绘制一帧并暂停。
- 页面隐藏、02 远离视口和减少动态效果模式下暂停 RAF。
- 01 与 02 的 WebGL 场景同时可见只发生在相邻转场窗口；离屏场景暂停自身更新。
- 屏幕壁纸与材质纹理按实际显示尺寸制作，控制总纹理内存和移动端清晰度。
- 避免 transmission pass；采用固定暖主光、轮廓光、环境光与常规 PBR 粗糙度。

## 8. 响应式与无障碍

- 1440×900、1280×720、1024×768、390×844、375×667 为首轮验收视口。
